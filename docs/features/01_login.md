# 機能別要件定義書：ログイン機能

[← 機能一覧に戻る](../features.md)

## 概要

メールアドレス＋パスワードによる新規登録・ログイン・ログアウトを提供する。認証にはJWT（JSON Web Token）を用い、ログイン後はトークンをクライアント側で保持してAPIリクエストに付与する。全機能の利用にはログインが必須。

認証にはアクセストークン（有効期限15分）とリフレッシュトークン（有効期限7日）の2種類を用いる。アクセストークンはJWTとして発行し、APIリクエストの認可に使用する。リフレッシュトークンはランダムな不透明トークンとして発行し、ハッシュ化した上でサーバー側DBに保存する。アクセストークンの有効期限が切れた場合、クライアントはリフレッシュトークンを用いて再ログインなしで新しいトークンペアを取得できる。

## 詳細仕様

### ユースケース1: 新規登録

1. ユーザーがメールアドレス・パスワード・ユーザー名（@handle）・表示名を入力する
2. サーバー側でメールアドレス・ユーザー名の重複チェックを行う
3. パスワードはBCryptでハッシュ化して`users`テーブルに保存する
4. 登録成功後、自動的にログイン状態にしてJWTを発行する

### ユースケース2: ログイン

1. ユーザーがメールアドレス・パスワードを入力する
2. サーバー側でメールアドレスに紐づくユーザーを検索し、BCryptでパスワード照合する
3. 一致すればJWTを発行してクライアントに返却する
4. 一致しなければエラーメッセージ（「メールアドレスまたはパスワードが正しくありません」）を返す

### ユースケース3: ログアウト

1. クライアントは保持しているリフレッシュトークンを`/api/auth/logout`に送信する
2. サーバー側は該当するリフレッシュトークンをDB上で失効させる（`revoked_at`をセット）
3. クライアント側は保持しているアクセストークン・リフレッシュトークンを破棄する

### ユースケース4: 認証状態の維持

1. クライアントはアクセストークンを保持し、以降のAPIリクエストの`Authorization: Bearer <token>`ヘッダーに付与する
2. サーバー側（Spring Security）はアクセストークンを検証し、有効期限切れ・改ざんされたトークンはリクエストを拒否する

### ユースケース5: トークンリフレッシュ

1. アクセストークンの有効期限が切れた（または切れる直前の）場合、クライアントは保持しているリフレッシュトークンを`/api/auth/refresh`に送信する
2. サーバー側はリフレッシュトークンをハッシュ化した上でDBと照合し、有効（未失効かつ有効期限内）であれば新しいアクセストークン・リフレッシュトークンのペアを発行する
3. 使用済みの古いリフレッシュトークンは同時に無効化される（ローテーション、使い捨て）
4. リフレッシュトークンが無効・期限切れの場合はエラーを返し、クライアントは再ログインが必要になる

## 権限

- 新規登録・ログインは未認証ユーザーが実行可能
- それ以外の全機能はログイン済みユーザーのみ実行可能

## 入出力・バリデーション

| 項目 | バリデーション |
|---|---|
| メールアドレス | 必須、メール形式、重複不可 |
| パスワード | 必須、8文字以上 |
| ユーザー名 | 必須、英数字と`_`のみ、3〜20文字、重複不可 |
| 表示名 | 必須、1〜50文字 |
