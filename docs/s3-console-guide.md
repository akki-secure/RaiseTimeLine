# AWSマネジメントコンソールでのS3確認方法

投稿画像の保存先であるS3バケット（`raisetimeline-images-174516979085`）を、AWS CLIではなくマネジメントコンソール（ブラウザ）から確認する手順。

## 前提

- 実装（[README.md](../README.md)）にある通り、バケット名・リージョンは `backend/src/main/resources/application.properties` の `app.s3.bucket-name` / `app.s3.region` で管理されている
- バケットはパブリックread可能（`s3:GetObject`のみ許可）に設定済みで、画像URLはブラウザから直接開ける
- AWS CLIでの確認方法（`aws s3 ls` 等）は [docs/aws.md](aws.md) の「S3・画像アップロードの流れ」を参照

## 手順

1. [AWSマネジメントコンソール](https://console.aws.amazon.com/)にサインインする
2. 画面右上でリージョンが**アジアパシフィック（東京）ap-northeast-1**になっていることを確認する
   - 別リージョンが選択されているとバケットが一覧に出てこない
3. 上部の検索バーに「S3」と入力し、サービス一覧から**S3**を開く
4. バケット一覧から `raisetimeline-images-174516979085` を選択する
5. 「オブジェクト」タブに、投稿時にアップロードされた画像がUUIDベースのファイル名（例: `3f2a1b9e-....jpg`）で並んでいることを確認する
   - アップロード日時の新しい順に並び替えると、直近の投稿確認がしやすい
6. 対象のオブジェクトをクリックすると、詳細画面で以下が確認できる
   - **オブジェクトURL**: アプリのタイムラインで表示される`<img src>`と同じ形式（`https://{バケット名}.s3.{リージョン}.amazonaws.com/{キー}`）になっているか
   - **サイズ**: 5MB以下になっているか（バックエンド側のバリデーションと一致するはず）
   - **最終更新**: 投稿した時刻とおおむね一致するか
7. 「開く」ボタンからオブジェクトURLに直接アクセスし、画像がブラウザで表示されることを確認する
   - パブリックreadを許可しているため、ログイン不要でそのまま表示される

## バケットのアクセス設定を確認する場合

設定に問題がないか確認したいときは、バケットの「アクセス許可」タブから以下を見る。

- **ブロックパブリックアクセス**: 4項目すべて「オフ」になっていること（オンだとパブリックread自体が機能しない）
- **バケットポリシー**: `Principal: "*"` に対して `s3:GetObject` のみが許可され、`PutObject`等の書き込み権限は含まれていないこと（書き込みはバックエンドのIAMユーザー権限のみで行う設計）

## トラブルシューティング

- **バケットが一覧に出てこない**: リージョンが東京（ap-northeast-1）になっているか確認する
- **画像がアップロードされていない**: バックエンドの起動ログでS3への書き込みエラー（`software.amazon.awssdk.services.s3.model.S3Exception`）が出ていないか、`~/.aws/credentials` の認証情報が有効か確認する
- **オブジェクトURLを開くとアクセス拒否になる**: バケットポリシーまたはパブリックアクセスブロック設定が変わっていないか確認する
